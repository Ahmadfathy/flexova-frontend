## 0) المبدأ الحاكم — «أدوار جاهزة لا مصفوفة خام»

هذا الموديول هو **طبقة الأمان والتحكّم** التي تحكم بقية النواة، ونقطة تفعيل متطلّب تحليل السوق: *الأمان والثقة من اليوم الأول — أي تسريب = موت السمعة*. أربع قواعد:

1. **قوالب أدوار جاهزة (Zero-config) لا مصفوفة:** الأدمن غير التقني يختار قالباً (مالك/مدير فرع/كاشير/محاسب/أمين مخزن/مندوب) ويعيّنه — لا يبني صلاحيات من الصفر. المصفوفة الدقيقة **مخفية** خلف وضع متقدّم للـ power users (progressive disclosure).
2. **RBAC + بُعدا نطاق (Scoping):** المستخدم ← دور (حزمة صلاحيات) + **نطاق فرعي** (أي فروع) + **نطاق صفّي** (بياناته فقط: الكاشير ورديته، المندوب عملاءه). يحلّ المتطلّب الذي طرحته التقارير.
3. **أقل امتياز افتراضاً (Least privilege / Default-deny):** ما لا يُمنَح صراحةً = ممنوع. الإجراءات الحسّاسة (حذف/إقفال/اعتماد/تجاوز) صلاحيات مرتفعة منفصلة.
4. **عزل multi-tenant صارم + أثر تدقيق:** بيانات كل عميل (tenant) معزولة تماماً؛ أدمن العميل يدير **داخل عميله فقط**. كل إجراء حسّاس يُسجَّل في **سجلّ تدقيق (Audit Log)** غير قابل للعبث — ركيزة الثقة المرئية.

> طبقة مشغّل المنصة (Flexova super-admin: إدارة الـ tenants/الباقات) **خارج نطاق واجهة العميل** — كونسول داخلي منفصل، يُوثَّق على حدة.

## 2) الكيانات (Data Model الظاهر)

| الكيان | الوصف | المالك |
|---|---|---|
| **المستخدم** (User) | هوية دخول (تليفون/بريد) + بيانات + حالة (نشط/موقوف) + تفضيلات | أدمن العميل |
| **الدور** (Role) | حزمة صلاحيات + نطاق؛ قالب جاهز أو مخصّص | النظام/الأدمن |
| **الصلاحية** (Permission) | مفتاح إجراء ذرّي (system-defined) — راجع §3 | النظام |
| **النطاق** (Scope) | الفروع المسموحة + قاعدة الرؤية الصفّية (الكل/الفرع/الذات) | تعيين |
| **الجلسة** (Session) | دخول نشط بجهاز/وقت؛ قابلة للإنهاء عن بُعد | النظام |
| **سياسة الأمان** (Security Policy) | كلمة السر، فرض 2FA، مهلة الجلسة | الأدمن (ضمن حدود المنصة) |
| **سجلّ التدقيق** (Audit Log) | مَن فعل ماذا ومتى — للإجراءات الحسّاسة (غير قابل للحذف) | النظام |
| **تفضيلات المستخدم** (Preferences) | الثيم/Layout/اللغة (ثيم العميل افتراضي + override للمستخدم — وضع داكن أولوية للمستخدم) | المستخدم |

**قرارات v1:**
- **هوية الدخول = التليفون أو البريد** + كلمة سر؛ **2FA متاح ومُوصى** (قابل للفرض على مستوى العميل لحساسية البيانات المالية/الضريبية).
- **Default-deny**؛ الإجراءات الحسّاسة صلاحيات منفصلة.

## 4) قوالب الأدوار الجاهزة (Default Templates)

تُحقَن عند الـ onboarding حسب النمط (متّسق مع «قوالب جاهزة لكل نشاط»):

| الدور | جوهره | نطاق نموذجي |
|---|---|---|
| **المالك (Owner)** | كل شيء (بما فيه الإدارة والمالية الكاملة) | كل الفروع |
| **مدير الفرع** | بيع/مخزون/تقارير فرعه، لا إدارة مستخدمين | فرعه |
| **الكاشير** | بيع وقبض و POS وتقرير وردية | ورديته (صفّي) |
| **المحاسب** | الوضع المحاسبي الكامل + التقارير المالية، لا حذف بيانات تشغيلية | حسب التعيين |
| **أمين المخزن** | المخزون والجرد والتحويلات | فرعه |
| **المندوب** | عملاؤه ومبيعاته وتحصيله | الذات (صفّي) |

كلها قابلة للنسخ والتعديل لإنشاء أدوار مخصّصة.

## 5) المسارات (User Flows)

### Flow 1 — إضافة/دعوة مستخدم
«＋مستخدم» → اسم + تليفون/بريد → **اختيار قالب دور** → نطاق الفرع (إن لزم) → إرسال دعوة (واتساب/بريد) → المستخدم يضبط كلمة سره. زمن قصير، بلا لمس المصفوفة.

### Flow 2 — إنشاء دور مخصّص (متقدّم)
نسخ قالب → فتح المصفوفة (مجمّعة بالموديول، toggles عالية المستوى تتوسّع للدقيق) → ضبط النطاق الفرعي/الصفّي → حفظ.

### Flow 3 — الدخول + 2FA
تليفون/بريد + كلمة سر → (إن مُفعّل) رمز ثانٍ → جلسة. «نسيت كلمة السر» عبر رمز للتليفون/البريد.

### Flow 4 — تعطيل/إيقاف مستخدم (Offboarding)
إيقاف فوري → إنهاء كل جلساته → منع الدخول؛ بياناته/أثره يبقى (لا حذف — متّسق مع قاعدة الأثر).

### Flow 5 — مراجعة سجلّ التدقيق
فلترة (مستخدم/إجراء/فترة/فرع) → عرض «مَن فعل ماذا ومتى» للإجراءات الحسّاسة → تصدير.

### Flow 6 — إجراء حسّاس
محاولة إجراء ⚠ بلا صلاحية → منع برسالة واضحة («تحتاج صلاحية X — راجع الأدمن»)؛ مع صلاحية → تأكيد صريح + تسجيل في الأثر. (workflow اعتماد متعدد الخطوات = نقطة مفتوحة.)

## 6) الشاشات والحقول والحالات

> التزام بالحالات الخمس (§7 أسس التصميم). الخاص بالموديول:

### 6.1 المستخدمون
قائمة (الاسم/الدور/الفرع/آخر دخول/الحالة)، دعوة، فلترة، حالة فارغة «ابدأ بدعوة فريقك».

### 6.2 كارت/تعديل المستخدم
الدور(الأدوار) + النطاق + الحالة + الجلسات النشطة (إنهاء عن بُعد) + إعادة تعيين 2FA.

### 6.3 الأدوار
القوالب الجاهزة + الأدوار المخصّصة، عدد المستخدمين بكل دور، نسخ/تعديل.

### 6.4 محرّر الدور (المصفوفة)
المصفوفة مجمّعة بالموديول، **toggle عالٍ** («وصول كامل للمبيعات») يتوسّع للمفاتيح الدقيقة؛ الإجراءات الحسّاسة ⚠ مميّزة بصرياً. ضبط النطاق الفرعي/الصفّي أسفل المصفوفة.
- مبدأ: معظم العملاء لا يفتحون هذه الشاشة إطلاقاً.

### 6.5 الأمان
سياسة كلمة السر، فرض/تفعيل 2FA، مهلة الجلسة، الأجهزة الموثوقة.

### 6.6 سجلّ التدقيق
جدول زمني للإجراءات الحسّاسة، فلترة وتصدير، غير قابل للتعديل.

### 6.7 الفروع والنطاق
إدارة الفروع وربط وصول المستخدمين بها (يغذّي النطاق في كل الموديولات والتقارير).

## 7) الحالات الحرجة الخاصة بالموديول

- **منع بصلاحية:** الإجراء غير المصرّح يُخفى أو يُعطَّل برسالة واضحة بالعامية (لا كود تقني).
- **آخر أدمن:** منع تعطيل/خفض آخر مستخدم يملك `admin.user.manage` (قفل أمان ضد فقدان السيطرة).
- **Offline:** الصلاحيات مُخزّنة محلياً للعمل offline (POS)؛ التغييرات تُطبَّق عند المزامنة؛ الدخول الأول يتطلب اتصالاً.
- **جلسة منتهية/مُنهاة عن بُعد:** خروج آمن فوري ورسالة واضحة.

## 9) قرارات هذا الموديول + نقاط مفتوحة

**مثبّتة ضمن v1:**
- RBAC + قوالب أدوار جاهزة per-archetype (المصفوفة للـ power users فقط).
- بُعدا نطاق: **فرعي + صفّي (own data)**.
- **Default-deny** + عزل صلاحيات الإجراءات الحسّاسة ⚠.
- **2FA متاح ومُوصى**، قابل للفرض على مستوى العميل.
- **Audit Log** للإجراءات الحسّاسة من اليوم الأول (غير قابل للحذف).
- عزل multi-tenant صارم؛ أدمن العميل داخل عميله فقط؛ كونسول المنصة منفصل.
- قفل «آخر أدمن»؛ تعطيل لا حذف (حفظ الأثر).
- كتالوج صلاحيات موحّد (§3) يجمع مفاتيح الموديولات السبعة.

**نقاط مفتوحة (لا تعطّل v1):**
1. **workflow اعتماد متعدد الخطوات** (مثلاً اعتماد مدير لخصم كبير) — v1 يكتفي بصلاحية مرتفعة؛ محرّك الاعتماد الكامل لاحقاً.
2. **SSO/هوية خارجية** — لاحقاً.
3. **صلاحيات على مستوى الحقل (field-level)** — لاحقاً؛ v1 = إجراء + نطاق فرعي/صفّي.
4. **تفويض مؤقت (delegation)** أثناء الإجازات — لاحقاً.
