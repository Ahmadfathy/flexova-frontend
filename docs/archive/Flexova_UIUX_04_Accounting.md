## 0) المبدأ الحاكم للموديول — «وجهان لنفس الدفتر»

الحسابات هي أصعب موديول في النواة لأنها تواجه مستخدمَين متناقضَين:
- **المالك غير التقني** (صاحب بقالة/ورشة): عايز يعرف *«كام في الدُرج، كام ليّا، كام عليّا، صرفت في إيه»* — مش عايز يسمع كلمة «قيد» أو «مدين/دائن».
- **المحاسب** (موجود عند جزء من العملاء فقط): عايز دليل حسابات، قيود مزدوجة، ميزان مراجعة، قوائم مالية.

الحل المعماري (تطبيق مباشر لمبدأَي *البساطة المتطرفة* + *الثقة المرئية*):

1. **وضعان للعرض (View Modes) يحكمهما الـ Role:**
   - **الوضع المبسّط (Owner mode):** خزينة · مصروفات · تحصيل · «ليّا/عليّا» · تدفق نقدي. لا قيود ولا دليل حسابات ظاهر.
   - **الوضع المحاسبي (Accountant mode):** كل ما سبق + دليل الحسابات + دفتر اليومية + ميزان المراجعة + القوائم المالية + الإقفال.
   - التبديل بصلاحية، والافتراضي للـ tenant = المبسّط (zero-config).

2. **محرّك القيد التلقائي (Auto-Posting Engine) خلف الكواليس:** كل مستند تشغيلي (فاتورة بيع، فاتورة شراء، مصروف، سند قبض/صرف، تشغيل رواتب) **يولّد قيد يومية مزدوج تلقائياً** عبر قواعد ترحيل (posting rules) جاهزة. المالك لا يراه إطلاقاً؛ المحاسب يراجعه ويدقّقه. هذا قلب الموديول: **GL حقيقي تحت غطاء بسيط.**

> النتيجة: عميل بلا محاسب يشغّل النظام بالكامل من الوضع المبسّط، ونفس البيانات تُنتج قوائم مالية صحيحة جاهزة لمحاسبه أو لمأمورية الضرائب.

## 1) خريطة الموديول

```
                     ┌─────────────────────────────────────┐
                     │      محرّك القيد التلقائي (GL Core)   │
                     │   posting rules → Journal Entries     │
                     └───────────────┬─────────────────────┘
        تغذية تلقائية (in) ▲          │          ▼ مخرجات (out)
   ┌──────────┬──────────┬───────────┴──┐   ┌──────────────────────┐
 المبيعات   المشتريات   الرواتب(HR)  المخزون│   ميزان المراجعة         │
 (AR ذمم)  (AP ذمم)    (مصروف أجور) (COGS │   قائمة الدخل (P&L)      │
                                  متوسط مرجّح)│   الميزانية (Balance)   │
                                          │   التدفقات النقدية        │
   ┌──────────────── إدخال مباشر (يدوي) ──┘   └──────────────────────┘
   │
 ┌─┴───────┬──────────┬───────────┬──────────┬──────────────┐
خزائن    بنوك      محافظ(Fawry) مصروفات   سندات قبض/صرف   قيد يدوي
نقدية    وتحويلات   /محافظ                  + تحويلات بين الخزائن
```

طبقتان: **طبقة العمليات اليومية** (يستخدمها المالك) فوق **طبقة الأستاذ العام** (يستهلكها المحاسب). الأولى تُغذّي الثانية آلياً.

## 2) الكيانات (Data Model الظاهر للمستخدم)

| الكيان | الوصف | المصدر |
|---|---|---|
| **دليل الحسابات** (Chart of Accounts) | شجرة حسابات هرمية بقالب مصري جاهز (5 مستويات رئيسية) | قالب + تعديل |
| **القيد** (Journal Entry) | حركة مزدوجة (مدين/دائن متوازنة) برقم تسلسلي وتاريخ ومرجع للمستند المصدر | تلقائي غالباً + يدوي |
| **الخزينة** (Cashbox) | حساب نقدي؛ متعددة (لكل فرع/وردية) | إعداد |
| **الحساب البنكي** (Bank Account) | رصيد بنكي، رقم حساب، عملة (EGP في v1) | إعداد |
| **المحفظة الإلكترونية** (e-Wallet) | Fawry / محفظة موبايل / بوابة دفع | إعداد |
| **المصروف** (Expense) | بند مصروف بفئة + مركز تكلفة + طريقة دفع | إدخال مباشر |
| **سند القبض** (Receipt Voucher) | تحصيل من عميل، يُخصم من ذمته، يربط بفاتورة/أكثر | إدخال / من المبيعات |
| **سند الصرف** (Payment Voucher) | دفع لمورد/مصروف، يُخصم من خزينة/بنك | إدخال / من المشتريات |
| **التحويل** (Transfer) | نقل رصيد بين خزينة↔بنك↔محفظة | إدخال |
| **الذمم المدينة** (Receivables/AR) | مستحق من العملاء | محسوبة من المبيعات |
| **الذمم الدائنة** (Payables/AP) | مستحق للموردين | محسوبة من المشتريات |
| **مركز التكلفة** (Cost Center) | **الفرع = الافتراضي الضمني**؛ مراكز حرّة (مشروع/قسم) اختيارية ومخفية حتى تُفعَّل | إعداد |
| **القيد الافتتاحي** (Opening Balance) | أرصدة بدء التشغيل (خزائن/AR/AP/مخزون/رأس مال) — قيد افتتاحي واحد متوازن | wizard onboarding |
| **الفترة المالية** (Fiscal Period) | شهر/سنة مالية بحالة (مفتوحة/مغلقة) | إعداد + إقفال |
| **التسوية البنكية** (Bank Reconciliation) | مطابقة كشف البنك بحركة النظام | عملية دورية |

**قرارات v1 مثبّتة على مستوى البيانات:**
- **EGP فقط** (لا multi-currency في v1 — الـ schema يحجز حقل `currency` و`exchange_rate` للاستيراد لاحقاً لكن لا UI لها).
- **ترقيم تسلسلي لكل فرع** (sequence per branch) لكل أنواع السندات والقيود.
- **التكلفة = المتوسط المرجّح** (weighted average) — تأتي محسوبة من المخزون؛ الحسابات تستهلك قيمة COGS فقط ولا تعيد حسابها.

## 3) محرّك القيد التلقائي (Posting Rules) — قلب الموديول

كل عملية تشغيلية تُترجَم لقيد متوازن دون تدخّل المستخدم. أمثلة القواعد (مبسّطة):

| الحدث (المصدر) | مدين (Dr) | دائن (Cr) |
|---|---|---|
| فاتورة بيع آجلة | ذمم العميل (AR) | إيرادات المبيعات + ضريبة القيمة المضافة المستحقة |
| فاتورة بيع نقدية | الخزينة | إيرادات + ضريبة |
| تكلفة البيع (COGS) | تكلفة البضاعة المباعة | المخزون (بالمتوسط المرجّح) |
| فاتورة شراء آجلة | المخزون/المصروف + ضريبة قابلة للخصم | ذمم المورد (AP) |
| سند قبض من عميل | الخزينة/البنك | ذمم العميل (AR) |
| سند صرف لمورد | ذمم المورد (AP) | الخزينة/البنك |
| مصروف نقدي | حساب المصروف (حسب الفئة) | الخزينة/البنك |
| تحويل خزينة→بنك | البنك | الخزينة |
| تشغيل رواتب (HR) | مصروف أجور | رواتب مستحقة/الخزينة |

**قواعد سلامة (تظهر للمحاسب فقط):**
- كل قيد **متوازن إجبارياً** (Σ مدين = Σ دائن)؛ النظام يرفض الحفظ غير المتوازن.
- القيد التلقائي **مقفول للتعديل المباشر**؛ تعديله يتم بتعديل المستند المصدر (يعيد توليد القيد) أو بقيد تسوية يدوي — حفاظاً على الـ audit trail.
- قيد في **فترة مغلقة** ممنوع؛ يتطلب إعادة فتح بصلاحية.

## 4) دليل الحسابات — القالب المصري الجاهز (Zero-config)

يُحقن للـ tenant قالب جاهز عند الـ onboarding (مبدأ «قوالب جاهزة لكل نشاط» من تحليل السوق). الهيكل الخماسي القياسي:

```
1 الأصول (Assets)            → خزينة · بنوك · محافظ · ذمم عملاء · مخزون · أصول ثابتة
2 الخصوم (Liabilities)       → ذمم موردين · ضرائب مستحقة · رواتب مستحقة · قروض
3 حقوق الملكية (Equity)      → رأس المال · أرباح محتجزة · جاري الشركاء
4 الإيرادات (Revenue)        → مبيعات · إيرادات خدمات · إيرادات أخرى
5 المصروفات (Expenses)       → تكلفة البضاعة المباعة · أجور · إيجار · كهرباء/مرافق · تسويق · مصروفات إدارية
```

المالك لا يرى هذا إطلاقاً (الوضع المبسّط). المحاسب يقدر يضيف/يعدّل/يربط حسابات فرعية. القالب يتمدّد لاحقاً بحسابات خاصة بالنمط القطاعي (مثلاً «مصنعية الذهب» في نمط Retail الخاص).

## 5) المسارات (User Flows)

### Flow 1 — تسجيل مصروف (الأكثر استخداماً للمالك)
زر «＋ مصروف» (متاح من لوحة المالية ومن الموبايل) → اختيار الفئة (قائمة أيقونية: إيجار/كهرباء/بنزين/مشتريات نثرية...) → المبلغ → طريقة الدفع (خزينة/بنك/محفظة) → مرفق اختياري (صورة الإيصال) → حفظ. **قيد تلقائي خلف الكواليس.** زمن الإدخال المستهدف < 15 ثانية.

### Flow 2 — تحصيل من عميل (سند قبض)
من ملف العميل أو من المبيعات «حصّل» → يظهر رصيده المستحق + قائمة فواتيره المفتوحة → إدخال المبلغ → **تخصيص تلقائي** (الأقدم أولاً) مع إمكانية تخصيص يدوي على فواتير بعينها → اختيار الخزينة المستلِمة → حفظ → إيصال قابل للطباعة/المشاركة (واتساب). يُحدّث رصيد العميل (AR) فوراً.

### Flow 3 — دفع لمورد (سند صرف)
نظير Flow 2 على جهة الـ AP، يُخصم من خزينة/بنك ويُقفل فواتير الشراء.

### Flow 4 — تحويل بين الخزائن
«تحويل» → من (خزينة) → إلى (بنك) → المبلغ → ملاحظة → حفظ. قيد تحويل تلقائي. (يدعم سيناريو «توريد كاش الفرع للبنك» اليومي.)

### Flow 5 — قيد يومية يدوي (محاسب فقط)
متاح في الوضع المحاسبي → جدول سطور (حساب/مدين/دائن/بيان/مركز تكلفة) → مؤشّر توازن لحظي (أخضر عند التساوي، أحمر مع الفرق) → لا حفظ قبل التوازن → ترحيل.

### Flow 6 — التسوية البنكية (دورية)
رفع/إدخال كشف البنك → النظام يطابق آلياً (مبلغ+تاريخ تقريبي) → المطابق يُعلَّم ✓، غير المطابق يظهر في عمودين (في البنك مش في النظام / في النظام مش في البنك) → المستخدم يربط أو ينشئ القيد الناقص → الرصيد الختامي يتساوى.

### Flow 7 — الإقفال المالي (شهري/سنوي)
قائمة فحص ما قبل الإقفال (Pre-close checklist): قيود غير مرحّلة؟ تسويات بنكية معلّقة؟ ذمم قديمة؟ → معاينة القوائم → **إقفال ناعم** (شهر: يُقفل الإدخال ويبقى قابلاً لإعادة الفتح) / **إقفال سنوي** (يرحّل صافي الربح لحقوق الملكية ويقفل الفترة بصلاحية عُليا).

### Flow 8 (خلف الكواليس) — الترحيل التلقائي
أي مستند مُعتمد في موديول آخر يطلق posting rule → يُنشئ/يُحدّث القيد → ينعكس فوراً على الأرصدة والـ KPIs. عند تعديل/إلغاء المستند، القيد يُعكَس (reversal) لا يُحذف.

### Flow 9 — الأرصدة الافتتاحية (أولوية onboarding)
عند بدء التشغيل، wizard من خطوات: رصيد كل خزينة/بنك → أرصدة العملاء (عليهم — AR) → أرصدة الموردين (ليهم — AP) → رصيد المخزون (يتكامل مع موديول المخزون) → رأس المال/جاري الشركاء. الفرق يُرحّل لحساب موازنة افتتاحي حتى يتوازن القيد. يدعم الاستيراد من Excel (CSV) لتسريع الهجرة من نظام قديم — رافعة تبديل (switching) ضد المنافس.

## 6) الشاشات والحقول والحالات

> كل شاشة تلتزم بالحالات الخمس من أسس التصميم §7 (Loading/Empty/Error/Empty-search/Offline) وبالـ tokens والمكوّنات. أذكر هنا الخاص بالموديول فقط.

### 6.1 لوحة المالية (Finance Dashboard) — الشاشة الرئيسية
**KPIs (بطاقات):** السيولة المتاحة (مجموع كل الخزائن+البنوك+المحافظ) · صافي التدفق النقدي اليوم/الشهر · إجمالي «ليّا» (AR) · إجمالي «عليّا» (AP) · مصروفات الشهر · صافي ربح تقديري (الوضع المبسّط يسمّيها «المكسب التقديري»).
**عناصر:** رسم تدفق نقدي أسبوعي (داخل/خارج)، أعلى 5 فئات مصروف، قائمة «مستحقات متأخرة» (عملاء فات ميعادهم) كـ pills تحذير.
- **Empty (عميل جديد):** بطاقات بصفر + بطاقة onboarding «ابدأ: سجّل رأس مالك الافتتاحي / أضف خزينة».
- **Offline:** بانر «غير متصل — الأرقام محسوبة حتى آخر مزامنة».

### 6.2 الخزائن والبنوك والمحافظ
شبكة بطاقات لكل خزينة/بنك/محفظة (الرصيد الحالي بـ `tabular-nums`) + زر دخول لكشف الحركة. كشف الحركة = جدول (تاريخ/بيان/داخل/خارج/الرصيد المتحرك) — **العمود الفقري** بنمط compact، رأس ثابت، فلترة بالتاريخ، تصدير.
- حالات الجدول: skeleton أثناء التحميل، empty («لا حركة بعد»)، خطأ بإعادة محاولة.

### 6.3 سند قبض / سند صرف
**حقول:** الطرف (عميل/مورد) · التاريخ · المبلغ · الخزينة/البنك/المحفظة · جدول تخصيص على الفواتير المفتوحة (مع باقي/زيادة كرصيد) · بيان · مرفق.
- **حالة الزيادة:** لو المبلغ > المستحق → خيار «دفعة مقدّمة (on account)».
- **Offline (POS):** سند القبض النقدي من الكاشير يُسجّل محلياً ويُزامن (حالة: محلي/قيد المزامنة/تمت).

### 6.4 المصروفات
قائمة + إدخال سريع (Flow 1). تصنيف أيقوني، فلترة بالفئة/الفترة/مركز التكلفة، صورة الإيصال مرفقة (للتدقيق وللـ ETA لاحقاً). حالة فارغة ودّية بزر «سجّل أول مصروف».

### 6.5 دفتر اليومية + القيد اليدوي (محاسب)
جدول القيود (رقم/تاريخ/بيان/مدين/دائن/المصدر). كل قيد قابل للفتح لرؤية سطوره ومرجع المستند. القيود التلقائية مميّزة بشارة «آلي» وغير قابلة للتعديل المباشر. القيد اليدوي بمؤشّر التوازن اللحظي (§Flow 5).

### 6.6 ميزان المراجعة (Trial Balance)
جدول الحسابات (رصيد افتتاحي/حركة مدين/حركة دائن/رصيد ختامي) لفترة محددة، مع إجماليات تتوازن في الأسفل. تصدير. حالة «الميزان غير متوازن» تظهر كـ alert أحمر مع زر تشخيص (نادر — يدل على خلل بيانات).

### 6.7 القوائم المالية
ثلاث قوائم بفلتر فترة: **قائمة الدخل (P&L)** · **الميزانية (Balance Sheet)** · **التدفقات النقدية (Cash Flow)**. عرض مبسّط افتراضي + زر «تفصيلي». تصدير PDF/Excel. (في الوضع المبسّط: تظهر «قائمة الدخل» فقط باسم «الأرباح والمصروفات» مبسّطة.)

### 6.8 التسوية البنكية
واجهة عمودين (§Flow 6) — مطابقة سحب/إفلات أو تلقائية، شريط تقدّم «3 من 18 بند بانتظار المطابقة»، إغلاق عند توازن الرصيد.

### 6.9 الإقفال المالي
معالج (wizard) متعدد الخطوات: فحص → معاينة قوائم → تأكيد. الإجراء حسّاس → تأكيد صريح (modal) + صلاحية. شارة حالة الفترة (مفتوحة/مقفلة) ظاهرة دائماً.

## 7) الحالات الحرجة الخاصة بالموديول

- **عدم التوازن:** أي محاولة حفظ قيد غير متوازن → منع + رسالة بالعامية («المدين والدائن مش متساويين — الفرق X ج.م»).
- **فترة مغلقة:** أي إدخال بتاريخ داخل فترة مقفلة → منع + اقتراح «سجّلها في الفترة المفتوحة» أو «اطلب إعادة فتح».
- **رصيد خزينة سالب:** تحذير (لا منع افتراضياً — السوق النقدي يسمح بسلف مؤقتة)، قابل للتشديد بالإعدادات.
- **Offline في الكاشير:** التحصيلات النقدية تُحفظ محلياً وتُرحّل للأستاذ العام عند المزامنة — الـ GL لا «يكذب» (لا يُظهر إيراداً قبل المزامنة في تقارير الـ back-office، مع بيان «بانتظار مزامنة كاشير X»).

## 8) التكاملات (Integrations)

| الموديول | الاتجاه | التفصيل |
|---|---|---|
| **المبيعات + ETA** | in | كل فاتورة → AR + إيراد + ضريبة. ربط حالة ETA بالقيد (الإيقاع المزدوج: B2B شبه لحظي / B2C طابور 24–72 ساعة — حالة الإرسال لا تمنع القيد المحاسبي). |
| **المشتريات** | in | فواتير → AP + مخزون/مصروف + ضريبة قابلة للخصم. |
| **المخزون** | in | COGS وتقييم المخزون **بالمتوسط المرجّح** (تُستهلك القيمة فقط). |
| **HR/الرواتب** | in | تشغيل الرواتب → مصروف أجور + مستحقات. |
| **بوابات الدفع المحلية** | in/out | Fawry/محافظ/تحويل كطرق دفع للسندات (حل مشكلة التحصيل من تحليل السوق). |
| **ETA — الضرائب** | out | حساب ضريبة القيمة المضافة المستحقة/القابلة للخصم؛ صافي الإقرار. (التفاصيل في موديول ETA.) |
| **التقارير** | out | يغذّي لوحات التقارير المركزية لاحقاً. |

## 10) قرارات هذا الموديول + نقاط مفتوحة

**معتمدة ضمن v1 (مثبّتة):**
- نظام «الوجهين» (مبسّط/محاسبي) بصلاحية، الافتراضي مبسّط.
- محرّك قيد تلقائي + GL مزدوج كامل خلف الكواليس (لا يُختصر).
- قالب دليل حسابات مصري جاهز عند الـ onboarding.
- EGP فقط v1 · ترقيم لكل فرع · COGS متوسط مرجّح من المخزون.
- إقفال شهري ناعم + سنوي صلب.
- **الأصول الثابتة:** تُسجَّل كبند فقط (تحت مجموعة الأصول)؛ **الإهلاك التلقائي وسجلّ الأصول مؤجّلان** لموديول لاحق (الإهلاك يدوي بقيد تسوية لو احتاجه المحاسب).
- **مراكز التكلفة:** اختيارية ومخفية افتراضياً، **الفرع = مركز التكلفة الضمني**؛ المراكز الحرّة تُفعَّل عند الحاجة (لأنماط المشاريع/المقاولات لاحقاً).
- **الدفعات المقدّمة/أرصدة العملاء الدائنة:** ضمن v1 مبسّطة — رصيد دائن على العميل يُخصم آلياً عند الفوترة (بلا deferred revenue معقّد).
- **الأرصدة الافتتاحية:** ضمن v1 كأولوية onboarding عبر wizard (Flow 9) مع استيراد CSV.

**نقاط مفتوحة متبقية (للمراحل اللاحقة، لا تعطّل v1):**
1. عمق سجلّ الأصول الثابتة والإهلاك المؤتمت — موديول مستقل لاحق.
2. multi-currency للاستيراد/التصدير — مع طبقة القطاعات الخاصة.

## 11) ما يبني عليه التالي (CRM)

الحسابات تسلّم لـ CRM: رصيد العميل (AR)، تاريخ التحصيلات، حد الائتمان (credit limit) كقيد على المبيعات الآجلة. موديول CRM يستهلك هذه الأرقام ولا يعيد حسابها.
