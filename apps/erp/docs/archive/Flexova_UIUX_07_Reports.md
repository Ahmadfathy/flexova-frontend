# Flexova — UI/UX التقارير ولوحات المتابعة (Reports & Dashboards)

> الطبقة 2 — موديول النواة رقم 7 (بعد: المخزون · المبيعات+ETA · المشتريات · الحسابات · CRM · HR).
> الإصدار: 1.0 — يونيو 2026
> يستند إلى: `Flexova_Design_Foundations.md` (الطبقة 1) + كل موديولات النواة (مصدر بياناته). لا يعيد تعريف الـ tokens/المكوّنات/الحالات — يستهلكها.

---

## 0) المبدأ الحاكم — «طبقتان فوق مصدر حقيقة واحد»

التقارير **مش موديول معاملات** — هو **طبقة استهلاك وتجميع** تقرأ من المخزون والمبيعات والمشتريات والحسابات وCRM وHR وتعرض. لا يملك بيانات يومية، يملك *تعريفات* التقارير واللوحات. أربع قواعد تحكمه:

1. **وجهان (متّسق مع الحسابات وHR):** لوحات وتقارير **جاهزة بسيطة** للمالك (بكسب ولا بخسر؟ مبيعاتي ماشية إزاي؟ مين عليه فلوس؟ إيه اللي قرب يخلص؟) + **منشئ تقارير موجّه** للمحاسب/المدير (تخصيص أعمدة وفلاتر وتجميع).
2. **الأداء قبل الزخرفة:** على أجهزة متواضعة وبيانات قد تكبر، التقارير تقرأ من **تجميعات محسوبة مسبقاً ومُخزّنة (pre-computed aggregates / cache)** قدر الإمكان، لا من المعاملات الخام لحظياً. تحديث شبه لحظي + زر «تحديث» يدوي.
3. **الثقة المرئية — كل رقم قابل للتتبّع (Drill-down):** أي قيمة في أي تقرير قابلة للنقر للوصول للمستندات المصدر. لا «أرقام معلّقة».
4. **التسليم استباقي:** المالك يستقبل **«ملخّص اليوم» على واتساب** آلياً — لا ينتظر فتح النظام (رافعة تمايُز ولزوم يومي).

> لا يُعيد هذا الموديول حساب أي رقم محسوب في موديوله الأصلي (مثلاً تقييم المخزون بالمتوسط المرجّح، أو AR من الحسابات) — يعرضه كما هو.

## 2) الكيانات (Data Model الظاهر)

> الموديول يملك *تعريفات* لا معاملات. البيانات الفعلية **مستهلَكة** من بقية النواة.

| الكيان | الوصف | المالك |
|---|---|---|
| **تعريف التقرير** (Report Definition) | تقرير جاهز من المكتبة (مصدر + أعمدة + فلاتر افتراضية) | النظام |
| **التقرير المحفوظ** (Saved Report) | نسخة مخصّصة بناها المستخدم (أعمدة/فلاتر/تجميع محفوظة) | المستخدم |
| **اللوحة** (Dashboard) | تجميعة ودجات بترتيب، افتراضية لكل دور/نمط | النظام/المستخدم |
| **الودجة** (Widget) | بطاقة KPI / رسم / قائمة / جدول صغير داخل لوحة | تعريف |
| **العرض المحفوظ** (Saved View / Filter) | فلتر/فترة محفوظة لإعادة الاستخدام | المستخدم |
| **الجدولة** (Scheduled Delivery) | إرسال دوري لتقرير (واتساب/PDF) بوقت ومستلمين | المستخدم |
| **التجميعات** (Aggregates/Cache) | طبقة محسوبة مسبقاً لخدمة الأداء (خلف الكواليس) | النظام |

**قرارات v1:**
- **EGP** فقط، **tabular-nums** لكل القيم، تصدير **PDF/Excel** أصيل.
- **النطاق حسب الدور/الفرع (data scoping):** كل تقرير محكوم بصلاحية رؤية ونطاق فرع (الكاشير يرى ورديته، مدير الفرع فرعه، المالك الكل) — التفاصيل في موديول الصلاحيات.

## 3) فئات التقارير الجاهزة (Library)

مجمّعة بالموديول المصدر:

| الفئة | أمثلة |
|---|---|
| **المبيعات** | مبيعات بالفترة/الفرع/الكاشير/المنتج/العميل · الأكثر مبيعاً · هامش الربح · المرتجعات |
| **المخزون** | الأرصدة · حركة صنف · بطيء/سريع الحركة · تحت الحد الأدنى · **تقييم المخزون (متوسط مرجّح)** · فروق الجرد |
| **المشتريات** | مشتريات بالمورد/الفترة · أرصدة الموردين · أداء التوريد |
| **المالية** | قائمة الدخل · الميزانية · التدفقات · المصروفات بالفئة · السيولة *(تُعرَض هنا، مصدرها الحسابات)* |
| **العملاء (CRM)** | **أعمار الديون (AR Aging)** · أنشط العملاء · المتعثّرون · الشرائح |
| **الموظفين (HR)** | تكلفة العمالة · العمولات المستحقّة/المدفوعة · الحضور والغياب |
| **الضرائب/ETA** | حالة الإرسال (مرسل/مرفوض/معلّق) · ملخّص الضريبة المستحقّة/القابلة للخصم → الإقرار · تمييز **Sandbox/Production** |
| **الوردية (POS)** | **تقرير الوردية (Z-report)** · النقدية المتوقعة مقابل الفعلية · الفروق |

## 4) لوحة ETA/الضرائب — تمايُز امتثالي

تطبيق مباشر للإيقاع المثبّت: اللوحة تُظهر **طابورين** — B2B (شبه لحظي/pre-clearance) و B2C (طابور النافذة 24–72 ساعة) — بحالة كل مستند (مرسل/مقبول/مرفوض/قيد الإرسال)، مع زر **إعادة إرسال** للمرفوض وسبب الرفض بالعامية. وملخّص ضريبي جاهز للإقرار. يميّز إرسال **Sandbox الافتراضي** عن Production بوضوح لمنع اللبس.

## 5) المسارات (User Flows)

### Flow 1 — اللوحة + drill-down
المالك يفتح اللوحة الافتراضية لدوره → KPIs ورسوم → نقر أي رقم → تفصيله → المستندات المصدر.

### Flow 2 — تقرير جاهز + فلترة + تصدير
مكتبة التقارير → اختيار تقرير → ضبط الفترة/الفرع/الفلاتر → عرض (جدول + رسم) → تصدير PDF/Excel أو مشاركة واتساب.

### Flow 3 — بناء تقرير مخصّص (Builder موجّه)
اختيار **المصدر** (مبيعات/مخزون/...) → اختيار الأعمدة → الفلاتر → التجميع (group by) والترتيب → معاينة → **حفظ** كتقرير محفوظ. (builder موجّه لا SQL — بساطة.)

### Flow 4 — جدولة ملخّص يومي
اختيار تقرير/لوحة → تكرار (يومي 9ص مثلاً) → مستلمون → قناة (واتساب/PDF) → حفظ. يصل «ملخّص اليوم» تلقائياً.

### Flow 5 — تخصيص اللوحة
وضع تحرير → إضافة/إزالة/ترتيب ودجات (سحب وإفلات يحترم RTL) → حفظ لكل مستخدم.

### Flow 6 — تقرير الوردية (Z-report) — يعمل offline
الكاشير يقفل الوردية → تقرير: مبيعات الوردية/طرق الدفع/النقدية المتوقعة → إدخال النقدية الفعلية → **الفرق**. **يعمل كاملاً offline** ويُزامن (متّسق مع POS offline-first).

## 6) الشاشات والحقول والحالات

> التزام بالحالات الخمس (§7 أسس التصميم). الخاص بالموديول:

### 6.1 الرئيسية / اللوحة (Dashboard home)
لوحة افتراضية حسب الدور/النمط (المالك: مالية+مبيعات؛ مدير المخزون: أرصدة+نواقص). ودجات KPI + رسوم خفيفة (CSS لا صور ثقيلة — أداء). زر «تحديث» + طابع آخر تحديث.
- **Loading:** skeletons للبطاقات والرسوم (إحساس أسرع — لا سبينر فارغ).
- **Empty (عميل جديد):** ودجات إرشادية «ابدأ البيع لترى تقاريرك».

### 6.2 مكتبة التقارير
شبكة مجمّعة بالفئة (§3)، بحث، المفضّلة، آخر المستخدَمة. التقارير المحفوظة في قسم منفصل.

### 6.3 عارض التقرير
جدول compact (`tabular-nums`، رأس ثابت، فرز) + رسم اختياري، شريط فلاتر علوي (فترة/فرع/تصنيف)، تصدير، drill-down على الخلايا.
- **Empty-filter:** «لا نتائج لهذا الفلتر» (متمايز عن empty الحقيقي) + اقتراح توسيع الفترة.
- **حساب ثقيل:** مؤشّر «بيتم التجهيز…» مع إمكانية متابعة العمل (لا تجميد).

### 6.4 منشئ التقرير المخصّص
خطوات §Flow 3 بواجهة موجّهة، معاينة حيّة، حفظ ومشاركة.

### 6.5 لوحة الضرائب/ETA
§4 — طابورا B2B/B2C، حالات، إعادة إرسال، ملخّص الإقرار، تمييز Sandbox/Production.

### 6.6 تقرير الوردية (Z-report)
§Flow 6 — يعمل offline، بحالة مزامنة واضحة (محلي/قيد المزامنة/تمت).

### 6.7 الجدولة والإرسال
قائمة الجدولات، إنشاء/تعديل، قنوات (واتساب/PDF)، سجلّ الإرسالات.

## 7) الحالات الحرجة الخاصة بالموديول

- **Offline:** الأرقام محسوبة حتى آخر مزامنة (بانر صريح)؛ تقرير الوردية يعمل محلياً كاملاً.
- **تأخّر التجميع (Staleness):** عرض طابع «محدّث منذ X دقيقة» + زر تحديث فوري عند الحاجة لدقّة لحظية.
- **نطاق غير مصرّح:** المستخدم لا يرى تقارير/فروعاً خارج صلاحيته (تُخفى لا تُعطّل برسالة).
- **بيانات كبيرة:** الترقيم/التحميل التدريجي بدل تجميد الشاشة.

## 8) التكاملات (Integrations)

| الموديول | الاتجاه | التفصيل |
|---|---|---|
| **كل موديولات النواة** | in (قراءة) | المصدر الوحيد للأرقام؛ لا إعادة حساب. |
| **ETA** | in | حالات الإرسال + الملخّص الضريبي + تمييز Sandbox/Production. |
| **واتساب / البريد** | out | تسليم الملخّصات والتقارير المجدوَلة. |
| **التصدير** | out | PDF/Excel أصيل (يخدم تسليم المحاسب/الضرائب). |
| **الصلاحيات** | in | نطاق الرؤية (دور/فرع/صف) يحكم كل تقرير ولوحة. |

## 9) الصلاحيات المطلوبة (input لموديول الصلاحيات)

`reports.view` · `reports.view_financial` (حسّاسة — قوائم مالية/أرباح) · `reports.view_all_branches` مقابل نطاق الفرع · `reports.build` · `reports.save` · `reports.schedule` · `reports.export` · `dashboard.customize` · `reports.eta.view`.

> النقطة المحورية: **النطاق الصفّي/الفرعي (row/branch scoping)** — الكاشير ورديته، المدير فرعه، المالك الكل. يُحسَم تفصيله في موديول الصلاحيات التالي.

## 10) قرارات هذا الموديول + نقاط مفتوحة

**مثبّتة ضمن v1:**
- وجهان: لوحات/تقارير جاهزة + منشئ موجّه (لا SQL).
- طبقة **تجميعات محسوبة مسبقاً (cache)** + تحديث شبه لحظي + تحديث يدوي (أداء).
- **Drill-down** من أي رقم للمصدر.
- **ملخّص يومي عبر واتساب** (تسليم استباقي).
- لوحة ETA بطابورَي B2B/B2C وتمييز Sandbox/Production.
- **تقرير الوردية (Z-report) offline-first**.
- نطاق حسب الدور/الفرع · تصدير PDF/Excel أصيل · EGP/tabular-nums.

**نقاط مفتوحة (لا تعطّل v1):**
1. **حداثة البيانات:** درجة «اللحظية» الافتراضية للوحات مقابل تكلفة الحساب (ترجيح: شبه لحظي بـ cache + تحديث يدوي).
2. **عمق المنشئ:** جداول محورية (pivot/cross-tab) متقدّمة — لاحقاً؛ v1 builder موجّه.
3. **تصدير خارجي/BI:** API أو Google Sheets للتقارير — لاحقاً.
4. **توحيد متعدد الفروع (Consolidation):** عمق المقارنة بين الفروع في لوحة واحدة.

---

## 11) ما يبني عليه التالي (الصلاحيات)

التقارير تطرح أوضح متطلّب على موديول الصلاحيات: **التحكّم الصفّي/الفرعي في الرؤية (row/branch-level scoping)** بالإضافة لصلاحيات الإجراءات. موديول الصلاحيات (الأخير في النواة) يوحّد كل مفاتيح الصلاحيات المطروحة عبر الموديولات الستة السابقة في نموذج أدوار وصلاحيات واحد.
