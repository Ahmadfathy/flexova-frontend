# Flexova — موديول المخزون والأصناف (Inventory & Items UI/UX)

> الطبقة 2 من الـ UI/UX Docs — **أول موديول في النواة**، والعمود الفقري الذي تستهلكه المبيعات والمشتريات وPOS لاحقاً.
> الإصدار: 1.0 — مايو 2026
> يستند إلى: `Project Brief` (القسم 3 — النواة) · `Market Research` (القسم 7 — متطلبات الـ Core) · `Design Foundations` (الطبقة 1 — tokens/مكوّنات/حالات).
> **قاعدة:** هذا المستند يستهلك أسس التصميم ولا يعيد تعريفها. أي token/مكوّن مذكور بالاسم مرجعه الطبقة 1.

## 0) نطاق الموديول وحدوده (Scope & Boundaries)

### 0.1 ما يغطيه هذا الموديول (Core)
الأصناف، التصنيفات، وحدات القياس وتحويلاتها، الباركود، المخازن/الفروع، الأرصدة، دفتر حركة الصنف، الجرد، التحويلات بين المخازن، التسويات، الأرصدة الافتتاحية، حدود إعادة الطلب، الاستيراد/التصدير الجماعي.

### 0.2 ما **لا** يغطيه (يُبنى فوقه في طبقة القطاعات)
هذه خصائص قطاعية تُركَّب فوق كيان الصنف عبر **نقاط امتداد (extension points)** محدّدة في القسم 2، ولا تُحمَّل على النواة:
- **Variants / Matrix** (مقاسات وألوان — موديل واحد بعدة SKUs) → النمط 1 / Retail-Clothing.
- **التشغيلات والصلاحية (Batches / Expiry)** → الصيدليات والمستلزمات الزراعية والأغذية.
- **البيع بالوزن (Scale / weight-based)** → الجزارة/الطازة.
- **Serial Number tracking** → الموبايلات/الإلكترونيات/الصيانة.
- **الأسعار المتدرّجة حسب الكمية/العميل** → النمط 13 / Wholesale.

> النواة تُصمَّم لتقبل هذه الامتدادات دون إعادة هيكلة (انظر 2.10).

### 0.3 علاقته بباقي موديولات النواة
| الموديول | العلاقة بالمخزون |
|---|---|
| المشتريات | فاتورة شراء/استلام → حركة **وارد** تزيد الرصيد وتحدّث التكلفة. |
| المبيعات + ETA | فاتورة بيع → حركة **منصرف** تنقص الرصيد. الصنف يحمل كود ETA ونوع الضريبة. |
| POS (قطاع لاحقاً) | بيع **offline-first** يولّد حركات منصرف تتزامن لاحقاً. |
| الحسابات | تقييم المخزون (valuation) يغذّي الميزان؛ القيد المحاسبي مكانه موديول الحسابات. |
| الصلاحيات | كل إجراء (إضافة/تعديل/تسوية/جرد) محكوم بدور المستخدم وبالفرع/المخزن المسموح له. |

## 1) خريطة الموديول (Module Map)

```
                         ┌────────────────────┐
            التصنيف ──────│      الصنف Item     │────── وحدات القياس (UoM + تحويلات)
          (شجري)         │  (قلب الموديول)     │────── باركود (متعدد)
                         └─────────┬──────────┘────── كود ETA / نوع الضريبة (نقطة تكامل)
                                   │
                          الرصيد (Item × Warehouse)
                                   │
   ┌──────────────┬────────────────┼────────────────┬───────────────┐
 رصيد افتتاحي     جرد            تحويل             تسوية         حركات بيع/شراء
 (Opening)     (Stocktake)    (Transfer)       (Adjustment)    (من موديولات أخرى)
   └──────────────┴────────────────┴────────────────┴───────────────┘
                                   │
                          دفتر حركة الصنف (Item Ledger)  ← السجل الموحّد لكل ما سبق
```

**القاعدة الذهبية:** لا يتغيّر أي رصيد إلا عبر **حركة (movement)** موثّقة. لا تعديل مباشر على رقم الرصيد. هذا أساس "الثقة المرئية" ويُمكّن التدقيق والـ offline-sync.

## 2) الكيانات والـ Data Model الظاهر للمستخدم

> هذه الحقول هي **ما يراه/يدخله المستخدم** — مش schema قاعدة البيانات. الإلزامي مُعلَّم ✱.

### 2.1 الصنف (Item)
| الحقل | النوع | ملاحظات |
|---|---|---|
| ✱ الاسم (عربي) | نص | الأساسي للعرض والبحث. |
| الاسم (إنجليزي) | نص | اختياري — يظهر في الواجهة الإنجليزية وفي ETA عند الحاجة. |
| ✱ الكود / SKU | نص | فريد لكل tenant. **توليد تلقائي** مع إمكانية التعديل. |
| ✱ نوع الصنف | اختيار | `مخزني (stocked)` · `خدمة (service)` · `غير مخزني (non-stock)`. الخدمة لا رصيد لها. |
| التصنيف | مرجع | من شجرة التصنيفات (2.3). |
| ✱ وحدة القياس الأساسية | مرجع | الوحدة الأصغر التي تُحفظ بها الأرصدة (2.2). |
| الباركود | نص/متعدد | صنف قد يحمل أكثر من باركود (لكل وحدة باركود). توليد داخلي لو فاضي. |
| الصورة | ملف | اختيارية (مفيدة جداً لـ POS لاحقاً). v1: صورة واحدة. |
| **التسعير** | | |
| سعر البيع | رقم | يُحدَّد عبر **قوائم الأسعار** (2.2.1) — قائمة افتراضية + قوائم إضافية قابلة للإسناد للعملاء. شامل/غير شامل الضريبة (إعداد على مستوى tenant). |
| سعر الشراء | رقم | آخر سعر شراء (للعرض) — التكلفة الفعلية تُحسب آلياً (2.7). |
| **الضريبة وETA** | | |
| نوع الضريبة (ETA Tax Type) | مرجع | من جدول أنواع الضرائب المعتمدة بالمنظومة (T1=VAT...). |
| ✱ عند تفعيل ETA: كود الصنف (EGS / GS1) | نص | شرط إصدار e-invoice صحيح — يُحذَّر منه هنا ويُمنع الإصدار بدونه في المبيعات. |
| **المخزون** | | |
| حد إعادة الطلب (Reorder level) | رقم | لكل مخزن أو إجمالي — يغذّي تنبيه "قارب النفاد". |
| الحد الأقصى | رقم | اختياري. |
| الحالة | اختيار | `نشط` · `موقوف (لا يظهر في البيع)`. |
| ملاحظات | نص | اختياري. |

### 2.2 وحدة القياس + التحويلات (UoM & Conversions)
- وحدة أساسية واحدة (base) تُخزَّن بها الأرصدة، + وحدات إضافية بمعامل تحويل.
- مثال: `الأساسية = علبة` ، `كرتونة = 24 علبة`. البيع/الشراء يمكن بأي وحدة، والخصم بالأساسية.
- لكل وحدة: الاسم، المعامل (factor)، باركود اختياري، وسعر بيع اختياري خاص بالوحدة.

### 2.2.1 قوائم الأسعار (Price Lists) — ضمن v1
- **قائمة افتراضية** (تجزئة) موجودة دائماً + قوائم إضافية (مثل: جملة، عميل مميز).
- لكل قائمة: الاسم، العملة (جنيه v1)، الحالة، وسعر بيع لكل صنف ضمنها.
- كل عميل/مجموعة عملاء لها **قائمة أسعار افتراضية**؛ الفاتورة تجلب سعر الصنف من قائمة العميل تلقائياً مع **override يدوي للسطر**.
- كسور الكمية المتدرّجة (quantity breaks) = تحسين لاحق يُبنى فوق نفس البنية في طبقة الجملة.

### 2.3 التصنيف (Category)
- شجري (Parent/Child) بمستويات بسيطة (نوصي بحدّ عملي = 3 مستويات لتجنّب التعقيد — مبدأ البساطة).
- حقول: الاسم، التصنيف الأب (اختياري). لا أرصدة على التصنيف — للتنظيم والفلترة والتقارير فقط.

### 2.4 المخزن / الفرع (Warehouse)
| الحقل | ملاحظات |
|---|---|
| ✱ الاسم | مثل: المخزن الرئيسي، فرع مدينة نصر. |
| الكود | اختياري. |
| الفرع المرتبط | لربط المخزن بفرع تشغيلي. |
| النوع | `بيع` · `تخزين` · `تالف/مرتجعات` (مخزن منطقي للهوالك). |
| الحالة | نشط/موقوف. |
| افتراضي للمستخدم/الفرع | يحدّد المخزن المختار تلقائياً في الفواتير. |

### 2.5 الرصيد (Stock Balance)
- ليس كياناً يُحرَّر يدوياً — هو **ناتج محسوب** من الحركات لكل (صنف × مخزن).
- يعرض: الكمية المتاحة، (اختياري لاحقاً: محجوز/قيد النقل)، آخر تكلفة/متوسط التكلفة، تاريخ آخر حركة.

### 2.6 دفتر حركة الصنف (Item Ledger / Movements)
سجل زمني لكل حركة على الصنف، لكل سطر:
`التاريخ · النوع (وارد/منصرف/تحويل/تسوية/افتتاحي/جرد) · المصدر (رقم فاتورة/مستند) · المخزن · الكمية (±) · الرصيد بعد الحركة · التكلفة · المستخدم`.

### 2.7 التكلفة (Costing) — *قرار معتمد*
- **متوسط مرجّح (Weighted Average)** كافتراضي — الأبسط والأشيع للـ SME المصري ويتجنّب تعقيد طبقات FIFO في الواجهة.
- **FIFO** كخيار لاحق على مستوى tenant (لا يظهر في v1 لتقليل العبء).
- المستخدم يرى "متوسط التكلفة" و"آخر سعر شراء" — لا يطلب منه فهم آلية الحساب.

### 2.8 مستند الجرد (Stocktake)
رأس: المخزن، التاريخ، **وضع الجرد**، الحالة (`مسودة → جارٍ العد → معتمد`). أسطر: الصنف، الكمية الدفترية (محسوبة)، الكمية الفعلية (مُدخلة)، الفرق. **الاعتماد يولّد تسوية تلقائية** بالفروقات.

**وضعا الجرد (يُختار عند الإنشاء — قرار معتمد):**
- **مُجمَّد (Freeze):** يُقفَل المخزن/النطاق المجرود ضد البيع والحركات أثناء العدّ → أدق نتيجة بلا "هدف متحرّك". موصى به للجرد الكامل/الدوري.
- **مفتوح (Live):** البيع مستمر أثناء العدّ؛ النظام يلتقط **snapshot** للرصيد الدفتري لحظة البدء ويحسب الفرق مقابله ثم يسوّي → للمحلات اللي ماتقدرش توقف البيع. افتراضي للجرد الجزئي.

### 2.9 مستند التحويل (Transfer) ومستند التسوية (Adjustment)
- **تحويل:** من مخزن ← إلى مخزن، أسطر (صنف/كمية)، ملاحظة. **v1: تحويل فوري** (قرار معتمد). خيار "تأكيد استلام" (in-transit بخطوتين) محجوز لمرحلة الجملة/اللوجستيات.
- **تسوية:** مخزن، أسطر (صنف، فرق ±)، **سبب إلزامي** من قائمة (`هالك` · `تالف` · `فرق جرد` · `هدية/عيّنة` · `تصحيح إدخال`).

### 2.10 نقاط الامتداد القطاعية (Extension Points)
الصنف يُعرّف **علامات قدرات (capability flags)** تظهر تبويبات/حقول إضافية فقط عند تفعيل الموديول القطاعي:
`has_variants` · `track_batch_expiry` · `sold_by_weight` · `track_serial`. (قوائم الأسعار أصبحت ضمن النواة — 2.2.1؛ وكسور الكمية المتدرّجة تحسين يُبنى فوقها.) النواة لا تعرف تفاصيل الباقي، فقط تحجز المكان.

## 3) تدفقات المستخدم (User Flows)

### 3.1 إضافة صنف — كامل
`زر "+ صنف جديد"` → نموذج بتبويبات (4.2) → الأساسي إلزامي، الباقي تدريجي → **حفظ** أو **حفظ وإضافة آخر**.
- لو ETA مفعّل وكود EGS فاضي → حفظ مسموح + **تنبيه (banner)** أن الصنف غير جاهز للفوترة الإلكترونية.

### 3.2 إضافة سريعة (Quick-add) — أثناء فاتورة/POS
مودال مصغّر: `الاسم ✱ · سعر البيع · (الوحدة الأساسية افتراضياً · كود تلقائي)` → حفظ → يُكمَّل لاحقاً. الصنف يُعلَّم **"غير مكتمل"** في القائمة. يدعم مبدأ البساطة وسرعة التشغيل.

### 3.3 استيراد جماعي (Bulk Import) — حرج للـ onboarding
`استيراد` → تنزيل قالب Excel → رفع → **شاشة معاينة وتحقّق**: مطابقة الأعمدة، تمييز الصفوف السليمة/المعطوبة بسبب الخطأ، إصلاح سريع أو تجاهل → تأكيد الاستيراد → تقرير نتيجة (نجح/فشل + التفاصيل). يربط مباشرة بمتطلب "قوالب جاهزة لكل نشاط" في تحليل السوق.

### 3.4 الجرد (Stocktake)
إنشاء جرد لمخزن → تعبئة الكميات الفعلية (يدوي أو **مسح باركود متتابع**) → مراجعة الفروقات → اعتماد → تُنشأ تسوية تلقائية. خيار "جرد جزئي" لتصنيف/مجموعة أصناف.

### 3.5 التحويل والتسوية
تحويل: اختيار من/إلى + أصناف → تأكيد. تسوية: اختيار مخزن + أصناف + سبب → تأكيد (إجراء حسّاس يتطلّب confirmation حسب الطبقة 1 §6.5).

### 3.6 البحث والمراجعة
بحث فوري بالكود/الاسم/الباركود → فتح بطاقة الصنف → تبويب "الحركة" لرؤية الـ ledger والرصيد لكل مخزن.

## 4) الشاشات (Screens)

> كل شاشة بيانات تلتزم بالحالات الخمس (الطبقة 1 §7) — مفصّلة في القسم 5.

### 4.1 قائمة الأصناف (Items List) — الشاشة الرئيسية
- **App Shell:** رأس + تنقّل (عمودي/أفقي حسب اختيار العميل) — كما في المعاينة.
- **رأس الصفحة:** عنوان "المخزون والأصناف" + إجراءات: `+ صنف جديد` (Primary) · `استيراد` · `تصدير` · `طباعة باركود`.
- **شريط أدوات:** بحث (بالكود/الاسم/الباركود) + فلاتر: التصنيف، المخزن، نوع الصنف، الحالة، "قارب النفاد"، نطاق سعر.
- **جدول (الطبقة 1 §6.3):** أعمدة — `صورة مصغّرة · الكود · الاسم · التصنيف · الوحدة · الرصيد (إجمالي/لكل مخزن) · سعر البيع · الحالة · إجراءات`.
  - الأرقام `tabular-nums` ومحاذاة يمين؛ الحالة عبر **Pills** (`قارب النفاد`=warning، `موقوف`=محايد، `غير مكتمل`=warning).
  - رأس ثابت، فرز بالأعمدة، تحديد متعدد، نمط **compact** متاح (بيانات كثيفة).
- **إجراءات جماعية (bulk):** تفعيل/إيقاف، تغيير تصنيف، طباعة باركود، تصدير، حذف (بتأكيد).
- **إجراء صف:** تعديل · حركة الصنف · تكرار · إيقاف.

### 4.2 بطاقة الصنف (إضافة/تعديل)
نموذج بـ **تبويبات** (مش صفحة واحدة طويلة — تطبيق البساطة):
1. **الأساسي:** الاسم ع/إن، الكود، نوع الصنف، التصنيف، الوحدة الأساسية، الباركود، الصورة، الحالة.
2. **التسعير والضريبة:** سعر البيع/الشراء، نوع ضريبة ETA، **كود EGS/GS1** (مع تلميح إرشادي).
3. **المخزون:** تتبّع الرصيد (لأنواع مخزني)، حد إعادة الطلب، **الأرصدة الافتتاحية لكل مخزن** (كمية + تكلفة).
4. **الوحدات:** الوحدات الإضافية + معاملات التحويل + باركود/سعر لكل وحدة.
5. *(يظهر شرطياً)* **خصائص قطاعية:** variants/batch/weight/serial — فقط لو الموديول القطاعي مفعّل (2.10).

التذييل ثابت: `حفظ` · `حفظ وإضافة آخر` · `إلغاء`. حالات الحقول (خطأ/مساعدة) كما في الطبقة 1 §6.2، محاذاة RTL.

### 4.3 المخازن (Warehouses)
قائمة بسيطة + نموذج (2.4). تمييز المخزن الافتراضي. لا يُحذف مخزن به رصيد (تنبيه واضح + اقتراح: حوّل الرصيد أولاً).

### 4.4 دفتر حركة الصنف (Item Ledger)
جدول زمني (2.6) + فلتر نطاق تاريخ ومخزن ونوع حركة. رأس يعرض: الرصيد الحالي لكل مخزن، متوسط التكلفة، قيمة المخزون. كل سطر يربط لمصدره (فاتورة/مستند).

### 4.5 الجرد (Stocktake)
رأس المستند + جدول أسطر (صنف · دفتري · فعلي · فرق) مع تلوين الفروق (نقص=danger، زيادة=success). إدخال سريع بالباركود. شريط ملخّص (عدد الأصناف، صافي الفرق، القيمة). زر **اعتماد** يطلب تأكيداً (يولّد تسوية). يحترم **وضع الجرد** (مُجمَّد/مفتوح) المحدّد عند الإنشاء (2.8).

### 4.6 التحويلات والتسويات
شاشتا مستند متشابهتان: رأس + أسطر + تأكيد. التسوية تُلزم بحقل **السبب**. كلاهما يظهر في ledger الصنف.

### 4.7 النواقص / إعادة الطلب (Low Stock)
عرض مفلتر للأصناف تحت حد إعادة الطلب (نفس بطاقة KPI "أصناف قاربت النفاد" في الـ Dashboard). إجراء سريع: تحديد → "إنشاء أمر شراء" (يسلّم للمشتريات لاحقاً).

## 5) الحالات (States) — لكل شاشة بيانات

| الحالة | التطبيق في المخزون |
|---|---|
| **تحميل** | Skeleton rows للجدول، مش سبينر فارغ. |
| **فارغ** | "لسه مفيش أصناف" + أيقونة + زرّان: `+ صنف جديد` و`استيراد من Excel`. لا شاشة بيضاء. |
| **خطأ** | رسالة بالعامية + سبب + `إعادة المحاولة`. لا أكواد تقنية. |
| **بحث فارغ** | "مفيش نتائج لـ …" + اقتراح تعديل البحث/مسح الفلاتر — متمايزة عن "فارغ". |
| **Offline (أولوية)** | مؤشّر offline دائم بالرأس. القراءة من نسخة محلية. الإضافة السريعة وحركات POS تُحفظ محلياً وتُعلَّم: `محلي / قيد المزامنة / تمت المزامنة / تعارض`. |

**تعارض الأرصدة (Sync Conflict):** الأرصدة لا تُكتب مباشرة بل تُعاد كـ **حركات**؛ عند عودة الاتصال تُطبَّق الحركات بالتتابع فلا "تكتب فوق بعض". التعارض الحقيقي (مثلاً تسوية يدوية متزامنة) يُعرض للمستخدم للحسم — لا حسم صامت.

---

## 6) التكاملات (Integrations)

- **ETA:** كل صنف مخزني/خدمي يحمل `نوع ضريبة` + `كود EGS/GS1`. الواجهة تُبرز نقص الكود وتمنع إصدار e-invoice بدونه (الحسم النهائي في موديول المبيعات+ETA). وحدات القياس تُربط بالوحدات المعتمدة بالمنظومة.
- **المشتريات / المبيعات:** تستهلك الصنف وتولّد حركات وارد/منصرف. quick-add متاح من داخلهما (3.2).
- **الباركود:** قراءة (USB/كاميرا) في الجرد والبيع؛ طباعة ليبل (مفرد/جماعي) بقالب قابل للضبط.
- **Excel:** استيراد (قالب + تحقّق) وتصدير (القائمة الحالية بالفلاتر المطبّقة).
- **POS (لاحقاً):** يقرأ الأصناف/الأرصدة ويبيع offline-first، ويزامن الحركات.

---

## 7) RTL وتعريب خاص بالموديول
- كل التخطيطات بالخصائص المنطقية (الطبقة 1 §10). عمود الإجراءات في نهاية السطر **منطقياً**.
- الأرقام الغربية افتراضياً للكميات/الأسعار + `tabular-nums`. العملة `ج.م` بعد الرقم.
- الكميات السالبة في التسويات/الفروق تُعرض بإشارة واضحة ولون دلالي، لا بالاعتماد على الموضع.
- أسماء الأصناف قد تخلط عربي/لاتيني/أرقام → يُختبر الـ bidi دائماً.

## 8) الأداء (Performance)
- جداول الأصناف قد تبلغ آلاف الصفوف → **افتراضية القائمة (virtualized list)** + بحث/فلترة من الخادم (server-side) + ترقيم/تمرير لا نهائي.
- الصور مصغّرة ومؤجّلة التحميل (lazy). تجنّب جلب كل الأرصدة لكل المخازن دفعة واحدة — تُجلب عند الحاجة.
- أداء قبل الزخرفة: لا أنميشن ثقيل في الجداول الكبيرة.

## 9) القرارات (كانت نقاطاً مفتوحة) — كلها محسومة لـ v1
1. **قوائم الأسعار (Price Lists)** — ✅ **محسومة (مُحدَّثة — عكس قرار سابق):** **ضمن v1، لا تأجيل** — قوائم أسعار متعددة قابلة للإسناد للعملاء (2.2.1). كسور الكمية المتدرّجة تبقى تحسيناً لاحقاً فوق نفس البنية في طبقة الجملة.
2. ~~In-transit للتحويلات~~ — ✅ **محسومة:** **تحويل فوري** في v1. خيار "تأكيد استلام" (in-transit بخطوتين) محجوز للجملة/اللوجستيات (2.9).
3. ~~تجميد المخزن أثناء الجرد~~ — ✅ **محسومة:** **الوضعان متاحان** ويُختار بينهما عند إنشاء الجرد (مُجمَّد / مفتوح، 2.8). الافتراضي: مفتوح للجزئي، مُجمَّد للكامل.
4. ~~Serial tracking~~ — ✅ **محسومة:** **امتداد قطاعي** عبر `track_serial` (إلكترونيات/صيانة)، وليس نواة. النواة تحجز الـ hook في model الحركات (0.2، 2.10).
5. ~~صور الأصناف في v1~~ — ✅ **محسومة:** الصور **مفعّلة من v1** (صورة واحدة لكل صنف، thumbnails مؤجّلة التحميل — §8). قيمة عالية لـ POS والتعرّف السريع.
6. ~~مستوى التكلفة~~ — ✅ **محسومة:** **متوسط مرجّح فقط** في v1؛ FIFO كخيار tenant لاحق (مفيد مع batch/expiry). دفتر الحركة يخزّن تكلفة كل حركة فيدعم التحويل لاحقاً (2.7).

## 10) ما يبني عليه هذا المستند لاحقاً
- **التالي مباشرة:** موديول **المبيعات + ETA** — يستهلك الصنف (سعر/ضريبة/كود EGS/الوحدات) ويولّد حركات منصرف، ويحسم منطق منع الإصدار عند نقص بيانات ETA.
- **لاحقاً في النواة:** المشتريات (وارد) → الحسابات (تقييم المخزون).
- **طبقة Retail/POS:** تضيف variants وبيع بالوزن وشبكة منتجات فوق نفس الكيانات والـ tokens.
