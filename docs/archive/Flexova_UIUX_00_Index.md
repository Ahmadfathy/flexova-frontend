## 2) الأنماط المعمارية المتكرّرة (DNA النواة)

تكرّرت عبر الموديولات وتُعتبر قواعد تصميم حاكمة للبناء:

1. **الوجهان (Two Faces):** وجه تشغيلي بسيط للمالك غير التقني + وجه متقدّم للـ power user، يحكمه الدور/الإعداد. (الحسابات: مبسّط/محاسبي · المشتريات: مباشر/دورة كاملة · HR: بسيط/قانوني · التقارير: لوحات جاهزة/منشئ · الصلاحيات: قوالب/مصفوفة.)
2. **مصدر حقيقة واحد (Single Source of Truth):** الكيان يُعرَّف مرة ويُستهلَك في كل مكان دون إعادة حساب (العميل · الصنف · الرصيد/AR · COGS متوسط مرجّح). التقارير والـ CRM **يعرضان ولا يحسبان**.
3. **محرّكات خلف الكواليس + ترحيل تلقائي:** كل مستند تشغيلي يولّد قيداً مزدوجاً تلقائياً (Auto-Posting) → GL حقيقي تحت غطاء بسيط؛ ومحرّك راتب مماثل.
4. **كشف تدريجي + قوالب جاهزة (Zero-config):** قوالب per-archetype (دليل حسابات · أدوار · تقارير) تُحقن عند الـ onboarding؛ التعقيد يُكشَف عند الطلب فقط.
5. **الثقة المرئية + Drill-down:** كل رقم قابل للتتبّع لمصدره؛ شاشات «مركز ETA / Inbound Hub / سجلّ تدقيق» تجعل الامتثال والمساءلة مرئيين.
6. **الأثر لا الحذف (Reversal not Delete):** التعديل/الإلغاء بقيد عكسي وحفظ الأثر — في الحسابات وHR والصلاحيات.
7. **جداول مُصدَّرة لا أرقام مدفونة (Versioned config):** ETA والضريبة والتأمينات تُدار كجداول قابلة للتهيئة والإصدار، لا hard-coded.
8. **Offline-first (خاصة POS):** البيع والتحصيل والوردية (Z-report) والبحث عن العملاء والصلاحيات تعمل offline وتُزامن بحالة واضحة (محلي/قيد المزامنة/تمت).
9. **واتساب-أولاً:** الفواتير/الإيصالات/التذكيرات/القسائم/الملخّص اليومي/الدعوات عبر واتساب.
10. **منع ناعم + تجاوز بصلاحية (Soft-block):** الخزينة السالبة · تجاوز الائتمان · الصافي السالب — تحذير لا منع، مع تجاوز موثّق بصلاحية (يلائم السوق النقدي/الآجل).

## 3) خريطة تدفّق البيانات بين الموديولات

```
 المخزون ──COGS/تقييم(متوسط مرجّح)──▶ الحسابات ◀──AP── المشتريات
   ▲                                  ▲ │ AR
   │ بضاعة                            │ │
 المبيعات+ETA ──إيراد/ضريبة/AR───────┘ │
   │ نوع العميل+الضريبي                 │ الرصيد/الائتمان/التحصيل
   ▼ يوجّه إيقاع ETA                    ▼
  CRM (العميل) ◀───────────────────────┘
   │ المندوب الموسوم على المعاملة
   ▼ أساس العمولة (مُحصَّل)
  HR/الرواتب ──قيد المرتبات/السلف──▶ الحسابات

 كل ما سبق ──(قراءة فقط)──▶ التقارير ──ملخّص واتساب/تصدير
 الصلاحيات (نطاق فرعي/صفّي) ──تحكم──▶ كل الموديولات + التقارير
```

## 4) القرارات الحاكمة المثبّتة (لا تُعاد مناقشتها)

**على مستوى المنتج/الرؤية:**
- MVP = Core كامل (8 موديولات). أول نمط بعده = **Retail/POS**.
- التخصيص: Layout عمودي/أفقي + ثيم من مجموعة + عربي رئيسي/إنجليزي.
- الثيمات 6 (nile/emerald/clay/royal/teal/graphite)، إطلاق 3 أولاً (nile+emerald+graphite).
- Dark/Light: يتبع النظام + override يدوي (**أولوية للمستخدم**).
- الخط: IBM Plex Sans Arabic. E-commerce تصوّر بصري مستقل بنفس الـ tokens.
- **التسعير: مؤجّل (نقطة مفتوحة وحيدة على مستوى المنتج).**

**عبر الموديولات (محسومة):**
- **EGP فقط v1** · **ترقيم تسلسلي لكل فرع** · **التكلفة = متوسط مرجّح** (تسلسل لكل فرع).
- **قوائم الأسعار ضمن v1** (عكس التأجيل) · العميل يُربَط بقائمة أسعار.
- **ETA إيقاع مزدوج:** B2B شبه لحظي (pre-clearance) / B2C طابور نافذة 24–72 ساعة (post-clearance) · **Sandbox افتراضي** مُميَّز عن Production · عدّاد النافذة ميزة حرجة.
- **onboarding + ETA UX = أولوية تمايُز داخل النواة** · العمق القطاعي المصري = تمايُز بعد النواة.
- الحسابات: الوجهان · قالب دليل حسابات مصري · أصول ثابتة تسجيل-فقط (إهلاك لاحقاً) · مراكز تكلفة اختيارية (الفرع افتراضي) · دفعات مقدّمة v1 · wizard أرصدة افتتاحية v1.
- CRM: تليفون مفتاح dedupe · عميل walk-in · ولاء مطفأ افتراضياً · حد ائتمان بمنع ناعم.
- HR: طبقة قانونية مطفأة افتراضياً (جداول versioned) · عمولة على المُحصَّل افتراضياً · سلف/قروض بصرف آلي.
- التقارير: تجميعات مسبقة (أداء) · drill-down · ملخّص يومي واتساب · Z-report offline.
- الصلاحيات: RBAC + قوالب · نطاق فرعي/صفّي · Default-deny · 2FA متاح/قابل للفرض · Audit Log · عزل multi-tenant.
