## 0) النطاق والحدود (Scope & Boundaries)

### 0.1 ما يغطيه
الموردين وكشوف حساباتهم، أوامر الشراء، استلام البضاعة، فواتير الشراء، مرتجعات الشراء، سندات الدفع للموردين، و**مطابقة فواتير ETA الواردة من الموردين** (لخصم ضريبة المدخلات).

### 0.2 ما لا يغطيه (يُبنى فوقه)
- **التخليص الجمركي والاستيراد المعقّد** (شحنات/عملات متعددة/مصاريف جمركية) → نمط خاص لاحق.
- **التصنيع/BOM** → نمط Manufacturing لاحق.
- **landed cost المتقدّم** → نقطة مفتوحة (§9).

### 0.3 العلاقة بباقي الموديولات
| الموديول | العلاقة |
|---|---|
| المخزون | الاستلام/الفاتورة تولّد حركة **وارد** وتحدّث **التكلفة المرجّحة** (Inventory §2.7)؛ تدعم الوحدات المتعددة (شراء بالكرتونة/تخزين بالقطعة). |
| الحسابات | فاتورة الشراء تزيد **رصيد المورد**؛ سند الدفع يخصم من الخزينة/البنك؛ القيد في موديول الحسابات. |
| المبيعات + ETA | **خصم ضريبة المدخلات** مرهون بفاتورة مورد إلكترونية صحيحة (ETA_Update §1.2/§5). |
| الصلاحيات | من يعتمد أمر شراء/يستلم/يدفع محكوم بالدور والفرع. |

## 1) خريطة الموديول (Module Map)

```
                  المورّد (Supplier)
                        │
            (طلب شراء داخلي — اختياري)
                        │
              أمر الشراء (PO) ───▶ استلام البضاعة (Goods Receipt) ───▶ المخزون (وارد + تكلفة مرجّحة)
                        │
                        ▼
        فاتورة الشراء (Purchase Invoice) ──┬──▶ رصيد المورد + الحسابات
                        │                   └──▶ ربط فاتورة ETA المورد (ضريبة المدخلات)
                        ▼
              سند دفع (Payment) ◀── الخزينة/البنك

        مرتجع شراء (Purchase Return) ───▶ المخزون (منصرف) + تقليل رصيد المورد
```

**مبدأ حاكم (بساطة متطرفة):** الافتراضي للـ SME هو **الشراء المباشر** (استلام + فوترة في مستند واحد). الدورة الكاملة (طلب → أمر → استلام → فاتورة) متاحة لمن يحتاجها، مخبّأة خلف وضع متقدّم.

## 2) الكيانات والـ Data Model الظاهر للمستخدم

### 2.1 المورّد (Supplier)
| الحقل | ملاحظات |
|---|---|
| ✱ الاسم | للعرض والبحث. |
| الكود | توليد تلقائي. |
| **الرقم الضريبي (TRN) + UIN** | لمطابقة فواتيره الإلكترونية (ETA) وخصم المدخلات. |
| شروط الدفع | نقدي / آجل (مدة) / حد ائتمان. |
| جهة الاتصال | هاتف/بريد/عنوان. |
| التصنيف | اختياري (محلي/مستورد، فئة). |
| الرصيد | **محسوب** من الفواتير والمرتجعات والمدفوعات (لا يُحرَّر يدوياً). |
| الحالة | نشط/موقوف. |

### 2.2 أمر الشراء (Purchase Order) — وضع متقدّم
رأس: المورد، التاريخ، تاريخ التوريد المتوقّع، المخزن المستلِم، الحالة (`مسودة → مُرسَل → مستلم جزئياً → مكتمل → ملغى`). أسطر: الصنف، الكمية، الوحدة، السعر، إجمالي السطر.

### 2.3 استلام البضاعة (Goods Receipt / إذن إضافة)
مرتبط بأمر شراء (أو مباشر)، أسطر بالكميات **المستلمة فعلاً** (قد تقل عن المطلوبة → استلام جزئي)، المخزن. **يولّد حركة وارد** ويحدّث التكلفة.

### 2.4 فاتورة الشراء (Purchase Invoice / Supplier Bill) — الكيان المحوري
**الرأس:** المورد، رقم فاتورة المورد، التاريخ، المخزن، طريقة الدفع، **ربط فاتورة ETA الواردة** (UUID — انظر 2.7).
**الأسطر:** الصنف · الكمية · الوحدة · سعر الشراء · خصم السطر · نوع/نسبة الضريبة · إجمالي السطر.
**الإجماليات:** قبل الخصم · الخصم · الضريبة (مدخلات) · **تكاليف إضافية** (اختياري — §9) · الإجمالي.
- تحدّث **آخر سعر شراء** و**التكلفة المرجّحة** للأصناف، وتزيد **رصيد المورد**.

### 2.5 مرتجع الشراء (Purchase Return / إشعار للمورد)
مرتبط بفاتورة شراء، أسطر مرتجعة + **سبب**، يولّد **منصرف** للمخزون ويقلّل رصيد المورد. يُرسَل كإشعار ETA عند اللزوم.

### 2.6 سند الدفع للمورد (Payment Voucher)
المورد/الفاتورة، المبلغ، طريقة الدفع، الخزينة/البنك. يدعم **دفع جزئي ومتعدد**، ويحدّث رصيد المورد وحالة الدفع.

### 2.7 فاتورة ETA الواردة (Inbound e-Invoice) — تمايُز "الامتثال كقيمة"
عند إصدار مورد فاتورة إلكترونية للمنشأة، تصلها عبر منظومة ETA. الكيان: `UUID · المورد · القيمة · الضريبة · الحالة (بانتظار/مقبولة/مرفوضة) · نافذة الرد (72 ساعة)`.
- **القبول/الرفض خلال النافذة** + **مطابقتها بفاتورة شراء داخلية** = شرط خصم ضريبة المدخلات.

## 3) تدفقات المستخدم (User Flows)

### 3.1 شراء مباشر (الافتراضي للـ SME)
`+ فاتورة شراء` → اختيار مورد → إضافة أصناف (بحث/باركود) + كميات/أسعار → حفظ → **وارد للمخزون + تحديث التكلفة + رصيد المورد** فوراً. (استلام + فوترة في خطوة واحدة.)

### 3.2 الدورة الكاملة (وضع متقدّم)
(طلب شراء) → أمر شراء → استلام (قد يكون جزئياً) → فاتورة شراء (مطابقة بسيطة مع المستلَم).

### 3.3 مرتجع شراء
فتح فاتورة شراء → "إنشاء مرتجع" → اختيار الأسطر + السبب → **منصرف** + تقليل رصيد المورد.

### 3.4 الدفع للمورد
من كشف حساب المورد أو فاتورة → سند دفع (جزئي/كامل) → تحديث الرصيد والحالة.

### 3.5 مطابقة فاتورة ETA واردة
مركز الفواتير الواردة → مراجعة فاتورة المورد → **قبول/رفض خلال 72 ساعة** → ربطها بفاتورة شراء (أو إنشاؤها منها مباشرة) → تُحتسب ضمن مدخلات الضريبة.

## 4) الشاشات (Screens)

### 4.1 الموردون (Suppliers)
قائمة + بطاقة مورد تتضمّن **كشف حساب** (الفواتير/المرتجعات/المدفوعات + الرصيد الجاري) وزر "سند دفع".

### 4.2 قائمة المشتريات (Purchases List)
أعمدة: `رقم · التاريخ · المورد · الإجمالي · حالة الاستلام · حالة الدفع (Pill) · حالة ETA الواردة (Pill) · إجراءات`. فلاتر: مورد، حالة دفع، حالة ETA، نطاق تاريخ.

### 4.3 محرّر فاتورة الشراء (الشاشة المحورية)
3 مناطق: **رأس** (مورد/تاريخ/مخزن/رقم فاتورة المورد/ربط ETA) · **شبكة أسطر** (بحث/باركود، إدخال كيبورد كامل، حساب لحظي) · **لوحة إجماليات + تكاليف إضافية اختيارية**. أزرار: `حفظ كمسودة` · `اعتماد` (يولّد الوارد ويحدّث التكلفة).

### 4.4 أمر الشراء + الاستلام
محرّر PO (وضع متقدّم) + شاشة استلام تدعم **الكميات المستلمة الجزئية** مقابل الأمر.

### 4.5 مرتجع الشراء
محرّر مربوط بالفاتورة الأصل، حقل **سبب** إلزامي، يعرض أثر المخزون والرصيد.

### 4.6 سند الدفع
من مورد/فاتورة، يدعم جزئي/متعدد، يحدّث الرصيد.

### 4.7 مركز فواتير ETA الواردة (Inbound Hub) — تمايُزي
فواتير الموردين الواردة من المنظومة: `بانتظار الرد (مع عدّاد 72 ساعة)` · `مقبولة` · `مرفوضة` · `غير مطابقة`. إجراءات: قبول/رفض، مطابقة/إنشاء فاتورة شراء منها. KPIs: قيمة مدخلات الضريبة القابلة للخصم، فواتير قاربت انتهاء نافذة الرد.

## 5) الحالات (States)

**حالة الاستلام:** `بانتظار` · `مستلم جزئياً` · `مكتمل`.
**حالة الدفع (Pills):** `مدفوعة` · `مدفوعة جزئياً` · `آجلة`.
**حالة ETA الواردة (Pills):** `بانتظار الرد` (warning + عدّاد) · `مقبولة` (success) · `مرفوضة` (danger) · `غير مطابقة` (محايد).

الحالات الخمس لكل شاشة بيانات (تحميل/فارغ/خطأ/بحث فارغ/offline) كما في الأسس §7. **Offline:** استلام/إدخال فاتورة الشراء يعمل محلياً ويتزامن (أقل حرجية من POS لكن نفس مبدأ "محلي/قيد المزامنة/تمت")؛ مطابقة ETA الواردة تتطلب اتصالاً (تُعرض حالتها بوضوح عند العودة).

## 6) التكاملات (Integrations)
- **المخزون:** وارد/منصرف + تحديث التكلفة المرجّحة + الوحدات المتعددة.
- **ETA (buyer-side):** استقبال فواتير الموردين، القبول/الرفض خلال 72 ساعة، ربط UUID لخصم المدخلات. *(يعتمد على توفّر واجهة الاستقبال في ETA SDK — يُحقَّق وقت البناء.)*
- **الحسابات:** رصيد المورد، سندات الدفع، الخزينة/البنك.
- **الدفع المحلي:** تحويل/محافظ لتسوية الموردين.

## 7) RTL والتعريب
أرقام غربية + `tabular-nums`؛ العملة `ج.م` (جنيه فقط v1)؛ الرقم الضريبي وUUID تُعرض LTR ضمن RTL (bidi مُختبَر).

## 8) الأداء
شبكة أسطر سريعة؛ قوائم مشتريات/موردين كبيرة بـ server-side pagination؛ مطابقة ETA الواردة لا تحجب الواجهة (غير متزامنة).

## 9) القرارات (كانت نقاطاً مفتوحة) — كلها محسومة لـ v1
1. ~~التكاليف الإضافية / landed cost~~ — ✅ **توزيع بسيط اختياري**: حقل "تكاليف إضافية" في فاتورة الشراء يتوزّع على الأصناف **بالتناسب بالقيمة** (تكلفة حقيقية أدق). الجمارك/الاستيراد المعقّد (عملات/شحنات) يُؤجَّل لنمط الاستيراد.
2. ~~طلب الشراء (Requisition)~~ — ✅ **نكتفي بأمر الشراء في v1** (الـ SME نادراً يفصل أدوار الطلب/الشراء). يُضاف لاحقاً عند الحاجة القطاعية.
3. ~~نوع المطابقة~~ — ✅ **ربط بسيط** (فاتورة ↔ استلام) مع إظهار الفروقات؛ لا مطابقة ثلاثية ثقيلة في v1.
4. ~~الاستلام الجزئي/المتعدد~~ — ✅ **مدعوم** — أمر الشراء يبقى مفتوحاً حتى يكتمل الاستلام.
5. ~~ETA buyer-side~~ — ✅ **نصمّم على أساس توفّر واجهة استقبال فواتير الموردين** (المشتري يُبلَّغ ويرفض خلال 72 ساعة)، مع **تحقّق تقني وقت البناء**؛ fallback = إدخال/استيراد يدوي لو الـ API محدوداً.

## 10) ما يبني عليه هذا المستند لاحقاً
- **التالي:** موديول **الحسابات** (يستهلك رصيد المورد والمدفوعات وتقييم المخزون والضريبة مدخلات/مخرجات).
- ثم CRM → HR → التقارير → الصلاحيات لإكمال النواة.
